# Project Explanation

## A. Simple explanation

A password is stronger when it is harder for an attacker to guess. This is influenced by length, uniqueness, predictability, common-password usage and personal context—not just the presence of uppercase letters, numbers and symbols.

A simple way to think about this project is:

**Length + Unpredictability + Pattern Resistance + Common-Password Checks + Context = Better Password Assessment**

The application accepts a password, analyzes it locally through several independent modules, calculates a transparent educational score, explains the weaknesses it found, and gives concrete improvements.

## B. Technical explanation

The application is a React frontend backed by a FastAPI service. The `/api/analyze` endpoint receives a password in the POST body and passes it through modular analyzers. The derived results are merged by the scoring engine and suggestion engine. Only aggregate-safe metadata is stored in SQLite.

## Password security fundamentals

### Authentication vs authorization

Authentication asks, “Who are you?” Authorization asks, “What are you allowed to access?” Passwords are an authentication factor; they do not decide authorization by themselves.

### Plaintext vs hash

**Plaintext password:** the original secret in readable form. Production authentication systems should not persist it.

**Password hash:** a one-way representation generated by a dedicated password-hashing function. It supports verification without requiring recovery of the original secret.

### Salt and key stretching

A salt is a unique random value used with password hashing so identical passwords do not simply produce identical stored results. Password-hashing functions are deliberately expensive compared with general-purpose hashes, increasing the work required for large numbers of guesses.

### MFA

Multi-factor authentication adds another factor such as a hardware key, authenticator app, or other approved method. A strong password alone does not prevent phishing, session theft, or other authentication threats.

### Credential stuffing

Credential stuffing is the automated testing of username/password pairs obtained from another compromise. Password uniqueness and MFA reduce the impact of this attack pattern.

### Password manager

A password manager can generate and store unique credentials and reduces the need for a person to memorize many arbitrary secrets.

### Passphrases

A passphrase is a longer secret made from multiple words. Randomly selected words can provide practical memorability while preserving useful length.

## Why composition rules alone are insufficient

A value such as `Password123!` contains several character types, but the structure is predictable. Attackers can try common words followed by common numbers and symbols. The analyzer therefore reports composition as one signal and emphasizes length and pattern resistance.

## Why entropy is limited

The theoretical estimate in this project uses:

`L × log2(N)`

where `L` is the password length and `N` is an assumed character pool. This is not an exact measure of a human-chosen password's guessing difficulty. The project deliberately shows the estimate next to a warning explaining that the random-selection assumption is usually unrealistic for human-selected passwords.

## Why MFA matters

NIST states that passwords are not phishing-resistant. Strong authentication therefore combines the password with appropriate additional controls and alternative authenticators where required.
